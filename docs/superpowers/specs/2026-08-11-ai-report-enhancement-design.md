# 千问大模型工单报告增强设计

## 1. 目标

在现有人员工单报告上增加可选的 AI 分析能力。主管仍先获得服务端确定性统计报告，再按需调用千问，对报告进行结构优化、整体信息总结、问题判断、风险提醒和后续建议。模型不可替代现有统计、绩效评分或权限判断。

首期使用阿里云百炼北京地域的 OpenAI 兼容接口与 `qwen3.6-flash`。接入层保持供应商中立，以后只修改环境变量即可切换其他兼容模型。

## 2. 用户体验

1. 主管进入“管理工作台 → 报告”，选择人员、日期和小区并生成原始报告。
2. 报告操作区增加“AI 优化报告”按钮，不自动调用模型，避免无意消耗免费额度。
3. 点击按钮后显示生成状态；成功后在原报告顶部绩效卡之后增加“AI 报告解读”。
4. AI 解读固定展示：
   - 整体摘要；
   - 工作亮点；
   - 主要问题；
   - 趋势判断；
   - 风险提醒；
   - 后续建议。
5. 复制、打印和 Word 导出包含 AI 解读；原始数字、绩效分和计算依据保持服务端数据，不允许模型修改。
6. 模型不可用、额度耗尽或超时时，原报告继续正常展示，并提示“AI 分析暂不可用，原始报告不受影响”。

## 3. 架构

新增三个职责清晰的单元：

- `services/ai-report.js`：脱敏、构造提示词、调用 OpenAI 兼容接口、校验结构化输出、生成缓存键。
- `routes/ai-reports.js`：身份校验、人员与小区范围授权、取得确定性报告、调用服务并返回结果。
- `public/js/staff-report.js`：触发 AI 分析并将结构化结果安全地渲染到现有报告。

服务端调用链：

```text
主管选择筛选条件
  → 现有 getStaffReport 生成确定性数据
  → 服务端脱敏并生成数据摘要
  → 查询相同报告数据的 AI 缓存
  → 未命中时调用千问
  → 校验并清洗 JSON
  → 保存缓存并返回前端
```

## 4. 接口

新增：

`POST /api/reports/staff/:staff_id/ai-analysis`

请求体：

```json
{
  "from": "2026-08-01",
  "to": "2026-08-31",
  "community_id": "default"
}
```

接口必须复用现有人员报告的权限规则：

- 主管只能分析本人和递归下级；
- 全局主管可分析全部授权人员；
- 普通员工即使直接调用接口也只能分析本人；
- 无权小区或人员返回 403；
- 日期范围无效返回 400。

成功响应：

```json
{
  "data": {
    "status": "ready",
    "cached": false,
    "model": "qwen3.6-flash",
    "promptVersion": "report-analysis-v1",
    "analysis": {
      "summary": "本期工单处理整体稳定……",
      "highlights": ["完成率较高"],
      "issues": ["重复报修集中在水暖类"],
      "trends": ["处理时长较上期趋于稳定"],
      "risks": ["高频问题可能形成集中投诉"],
      "recommendations": ["对水暖高频点位开展专项巡检"]
    }
  }
}
```

## 5. 模型输入与隐私

模型只接收完成分析所需的聚合数据：

- 统计日期范围；
- 岗位类型，不发送人员姓名；
- 工单接收、完成、处理中、搁置、退回数量；
- 平均处理时长、SLA 按时率；
- 分类分布、复发数量、多人反馈数量；
- 服务端绩效综合分、等级、三项分值和样本数。

以下内容不得发送：

- 姓名、手机号、出生年月、入职日期；
- 用户 ID、人员 ID、工单 ID、小区 ID；
- 房号、楼栋、精确地址；
- 居民姓名、联系方式；
- 原始备注、投诉原文、图片和附件；
- Token、API Key 或其他环境变量。

小区在提示词中统一表示为“所选小区”，人员统一表示为“所选员工”。首期不发送原始工单描述，从数据源上降低提示词注入与个人信息泄露风险。

## 6. 结构化输出与防护

- 使用 Chat Completions 的 JSON 输出模式；如果模型不支持或返回非 JSON，服务端只允许一次 JSON 修复解析，不再次调用模型。
- 服务端只接受 `summary`、`highlights`、`issues`、`trends`、`risks`、`recommendations` 六个字段。
- `summary` 最长 600 个中文字符；每个数组最多 6 项，每项最长 200 个字符。
- 删除 HTML 标签、控制字符和未知字段；前端仍使用文本节点或转义后的 HTML，禁止直接执行模型返回的 HTML。
- 提示词明确要求不得编造工单、数字、人员评价或法律结论；没有足够证据时使用“数据不足以判断”。
- 模型生成内容标注为“AI 建议，仅供管理参考”。

## 7. 缓存与免费额度保护

新增 `ai_report_analyses` 表，字段包括：

- `id`；
- `staff_profile_id`；
- `community_id`；
- `range_from`、`range_to`；
- `report_hash`；
- `model`；
- `prompt_version`；
- `analysis_json`；
- `created_by_user_id`；
- `created_at`。

`report_hash + model + prompt_version` 建唯一索引。`report_hash` 由脱敏后的确定性报告 JSON 生成 SHA-256；报告数据不变时重复点击直接返回缓存，不再次消耗 Token。工单数据、绩效或筛选条件变化后哈希变化，自动生成新分析。

单用户 AI 分析接口限速为每分钟 5 次。调用超时默认 30 秒，最多重试一次且仅重试网络错误或 429/5xx；配额耗尽、鉴权失败和参数错误不重试。

## 8. 环境变量

Render 服务端配置：

```text
AI_REPORT_ENABLED=true
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_API_KEY=<百炼通用 API Key>
AI_MODEL=qwen3.6-flash
AI_TIMEOUT_MS=30000
AI_REPORT_PROMPT_VERSION=report-analysis-v1
```

`AI_API_KEY` 只能存在于 Render 环境变量中，不写入仓库、数据库、前端或日志。百炼侧开启“免费额度用完即停”。

未配置 `AI_REPORT_ENABLED=true` 或 `AI_API_KEY` 时，接口返回 503 与稳定错误码 `AI_REPORT_NOT_CONFIGURED`，页面隐藏或禁用 AI 按钮并说明尚未配置。

## 9. 错误处理

稳定错误码：

- `AI_REPORT_NOT_CONFIGURED`：未启用或缺少密钥；
- `AI_REPORT_QUOTA_EXHAUSTED`：免费额度耗尽；
- `AI_REPORT_RATE_LIMITED`：调用过于频繁；
- `AI_REPORT_TIMEOUT`：模型超时；
- `AI_REPORT_INVALID_RESPONSE`：模型响应格式无效；
- `AI_REPORT_PROVIDER_ERROR`：其他供应商错误。

错误响应不包含供应商原始响应、请求正文、API Key、完整提示词或内部堆栈。

## 10. 依赖与调用实现

项目已经依赖 `node-fetch`，首期直接调用 OpenAI 兼容 HTTP 接口，不引入 OpenAI SDK，以减少依赖和部署体积。服务端请求使用：

- `POST {AI_BASE_URL}/chat/completions`；
- `Authorization: Bearer {AI_API_KEY}`；
- `Content-Type: application/json`；
- `model: AI_MODEL`；
- 较低随机性，保证报告稳定；
- 限制最大输出 Token。

供应商差异只存在于环境变量和错误映射层，业务报告、缓存和前端不依赖千问专有字段。

## 11. 测试与验收

### 服务端

- 未登录、越权人员和越权小区不能调用；
- 脱敏载荷中不存在姓名、手机号、ID、地址和原始备注；
- 提示词输入只包含聚合统计和服务端绩效；
- 正常 JSON 响应被校验并返回；
- 非 JSON、超长字段、HTML 和未知字段被拒绝或清洗；
- 相同报告第二次调用命中缓存且不会再次请求模型；
- 报告变化后缓存失效；
- 超时、429、额度耗尽、401 和 5xx 映射为稳定错误码；
- API Key 不出现在错误响应或日志中。

### 前端

- AI 按钮只在确定性报告成功后可用；
- 加载期间不可重复点击；
- AI 内容显示在报告内并参与复制、打印和 Word 导出；
- AI 失败时原报告仍完整可用；
- 页面显示“AI 建议，仅供管理参考”；
- 模型返回文本不能注入 HTML 或脚本。

### 生产验收

- Render 配置千问环境变量后可生成一次分析；
- 再次点击相同报告显示缓存结果；
- 修改日期范围后生成新的分析；
- 关闭 AI 或使用无效密钥时原始报告不受影响；
- Supabase 持久化同步后，服务重启仍可读取已有分析缓存。

## 12. 非本轮范围

- 让模型修改服务端绩效得分；
- 自动读取图片、附件或投诉原文；
- 自动发送报告给员工或业主；
- 自动执行模型建议；
- 联网搜索和外部知识库；
- 多轮对话式追问；
- 永久免费承诺或自动切换到付费模型。

## 13. 完成定义

- 主管可在现有报告中按需生成 AI 解读；
- AI 输出包含整体摘要、亮点、问题、趋势、风险和建议；
- 原始统计和绩效始终由服务端计算且不被模型修改；
- 敏感字段不进入模型输入；
- 缓存、限速、超时和额度耗尽回退均生效；
- 未配置或调用失败时原报告保持可用；
- 专项测试与生产关键路径验证通过。
