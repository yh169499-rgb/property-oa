# 独立空白主管账号与系统标题设计

## 目标

在不修改既有测试账号、工单、排班、请假、流转、绩效和报告数据的前提下，新增一个独立的最高权限主管账号，并让多个主管各自管理不超过 4 名在职人员。同时去掉页面中的“全流程测试小区”等测试环境标题，只显示“工单系统”。

## 方案

1. 增加幂等的主管账号迁移服务。迁移只创建或更新指定手机号对应的主管档案，不触碰业务表；新账号不绑定任何下属，因而没有 mock 业务数据。
2. 主管创建普通人员时，以当前登录主管档案作为 `manager_id`，容量按主管分别计算；每名主管独立限制 4 人，既有单主管数据继续兼容。
3. 生产启动通过独立环境开关执行一次迁移，密码只从服务端环境变量读取，不写入代码或日志。迁移重复执行不会重复创建账号。
4. 前端 logo 固定显示“工单系统”，不再把当前小区名称拼接到标题中。

## 数据与错误处理

- 新主管手机号若不存在则创建 `users` 与 `staff_profiles`；若已存在且为主管则幂等更新；若已存在但不是主管则返回冲突并停止，不提权既有账号。
- 新主管档案的 `manager_id` 固定为空、`employment_status` 为 `active`。
- 人员创建、调整直属主管仍使用总人数 4 人及岗位容量校验；容量按目标主管统计。
- 迁移失败时启动失败并给出明确配置错误；未开启迁移时不改变现有启动行为。

## 验证

- 单元测试覆盖多主管按当前操作人分配人员、各自 4 人容量、手机号冲突和迁移幂等。
- 前端静态测试确认标题只显示“工单系统”。
- 运行相关 Node 测试、语法检查、`git diff --check`。
