# 班次模板、统一日程与个人日程设计规格

## 1. 目标

在现有人员、排班、考勤、工单和“我的”页面基础上，完成以下体验闭环：

1. 主管可以在“管理工作台 → 设置”维护班次模板。
2. 主管可以在“管理工作台 → 排班”查看和维护全员日程。
3. 师傅/管家可以在“我的”看到自己的排班、考勤和工单时间块。
4. 所有一级页面采用统一的蓝色渐变信息头、白色圆角卡片和一致的排版节奏。
5. 日程、考勤和工单全部以服务端数据为准，避免页面 localStorage 与数据库出现两套口径。
6. 为测试账号补充可重复执行的模拟班次、工单和考勤数据，便于验证页面。

## 2. 当前问题

- 班次模板接口已经存在，但前端没有模板新增、编辑、删除入口。
- 管理工作台的排班页只能读取模板并创建排班；数据库没有模板时，“上班”无法保存。
- 旧版 `public/app.js` 保留了一段师傅时间轴代码，但新版页面没有可见入口，也没有和服务端排班表统一聚合。
- “我的”目前展示档案、统计和实际考勤记录，没有展示排班和工单时间块。
- 管理工作台、工单详情和个人中心的视觉层级不一致。

## 3. 视觉规范

### 3.1 页面骨架

每个一级页面采用以下结构：

```text
┌──────────────────────────────────────────────────────┐
│ 蓝色渐变信息头：页面眉题 / 页面标题 / 摘要 / 周期切换 │
└──────────────────────────────────────────────────────┘
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ 白色圆角卡片 │ │ 白色圆角卡片 │ │ 白色圆角卡片 │
└──────────────┘ └──────────────┘ └──────────────┘
```

### 3.2 设计令牌

- 主渐变：`#123f78 → #1f7cf0`，用于页面头部和重点状态。
- 页面背景：`#f5f8fc`。
- 卡片：`#ffffff`，圆角 `18px`，细边框 `#e6edf6`，阴影保持轻量。
- 正文：深蓝灰 `#18324f`；辅助文字 `#6f8198`。
- 交互主色：`#2f6fed`；成功 `#22a06b`；警告 `#e8942e`；危险 `#d94b5c`。
- 页面头部内的白色文字保持高对比度，按钮使用半透明白色底或白色实底。
- 统一响应式断点：`768px`；窄屏保留卡片结构，时间轴改为纵向议程。

### 3.3 页面头部文案

| 页面 | 眉题 | 标题 | 摘要 |
| --- | --- | --- | --- |
| 我的 | 员工个人中心 / 主管个人中心 | 当前用户姓名 | 岗位 · 今日/月度/年度工作概览 |
| 管理工作台 | 运营控制中心 | 管理工作台 | 组织、排班、审核、报告与系统设置 |
| 排班 | 日程安排 | 团队排班 | 日期、人员和班次安排 |
| 模板设置 | 排班配置 | 班次模板 | 统一定义上下班时间和迟到宽限 |
| 工单详情 | 服务记录 | 报修工单 | 小区、类别、处理状态和当前负责人 |

## 4. 功能设计

### 4.1 班次模板管理

入口：`管理工作台 → 设置 → 班次模板`。

模板字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 如“标准白班”“夜班” |
| 上班时间 | `HH:mm` |
| 下班时间 | `HH:mm`；早于上班时间时按跨夜班处理 |
| 颜色 | 用于排班卡片和日历时间块 |
| 迟到宽限 | 非负整数分钟 |

交互：

- 设置页以卡片列表展示模板名称、时间范围、跨夜标识、颜色和宽限分钟。
- 新增和编辑使用同一表单；保存前校验名称、时间和宽限分钟。
- 删除前显示确认；如果模板已被排班使用，提示先调整已有排班，不直接破坏历史记录。
- 主管以外的用户可以查看自己的排班结果，但不能进入模板写操作。

现有接口：

- `GET /api/shift-templates`
- `POST /api/shift-templates`
- `PATCH /api/shift-templates/:id`

如需删除，新增 `DELETE /api/shift-templates/:id`，服务端检查是否存在 `shift_assignments.template_id` 引用；存在引用时返回明确错误码 `SHIFT_TEMPLATE_IN_USE`。

### 4.2 主管排班

入口：`管理工作台 → 排班`。

- 顶部使用统一蓝色渐变信息头。
- 筛选条件保留日期、人员、类型、模板和请假类型。
- 日程列表读取 `shift_assignments`，日历聚合读取 `/api/calendar/day`。
- “上班”必须选择模板；“休息”和“请假”不需要模板。
- 单人新增和批量排班均使用同一套模板数据。
- 冲突覆盖、重复排班、跨夜班在保存前给出明确提示。

### 4.3 师傅/管家个人日程

入口：`我的` 页面新增“我的日程”卡片，不增加新的顶级导航。

- 普通人员只请求自己的排班和工单，不允许通过 query 参数查看其他人员。
- 桌面端显示日期切换、班次卡片、考勤状态和工单时间块。
- 窄屏按日期显示纵向议程：班次 → 考勤 → 工单，避免横向滚动。
- 当前日期默认展示今日；支持切换前后日期和“本周/本月”摘要。
- 没有排班时显示“今天未安排班次”；没有工单时显示“暂无工单时间块”。

数据来源：

```text
GET /api/calendar/day?date=YYYY-MM-DD
GET /api/me/attendance?month=YYYY-MM
GET /api/me/stats?period=day|month|year
```

服务端根据登录用户身份强制限制日程范围，前端不自行拼接其他人员 ID。

### 4.4 工单详情与统一视觉

- 工单详情抽屉保留截图中的简洁白底标题层级。
- 详情顶部增加蓝色小型状态带，不改变现有字段和操作流程。
- 负责人、工单状态、创建时间、完成时间和处理时长使用统一信息项卡片。
- 工单时间块与日程页面使用同一颜色和时间格式，保证跨页面可识别。

## 5. 数据打通

统一数据流：

```text
shift_templates
      ↓ template_id
shift_assignments ─────┐
      ↓                 │
attendance_records     │
      ↓                 │
calendar 聚合服务  ← tickets / ticket_activity_logs
      ↓
管理工作台排班 + 我的日程 + 主管报告
```

规则：

- 班次时间来自 `shift_templates`；跨夜班由服务端 `resolveShiftWindow` 计算。
- 实际考勤来自 `attendance_records`，不再用排班天数估算出勤。
- 工单时间块优先使用 `assigned_at`，缺失时按现有兼容规则回退到 `created`。
- 主管按组织树范围查看团队；普通人员只能查看本人。
- localStorage 只保存页面筛选偏好，不保存排班、考勤和工单事实数据。

## 6. 测试模拟数据

为测试账号 `13800000011`（主管）、`13800000012`（师傅）、`13800000013`（管家）准备可重复执行的种子脚本，使用固定前缀和幂等键，避免重复插入：

- 3 个班次模板：标准白班、晚班、休息日不使用模板。
- 最近 7 天的上班、休息和请假排班。
- 最近 7 天的正常、迟到和休息考勤记录。
- 至少 6 张工单：待处理、处理中、已完成、待确认，负责人覆盖师傅和管家。
- 至少 1 个日历时间重叠冲突，验证冲突提示。
- 至少 1 张跨夜班次，验证时间轴边界。

种子脚本必须：

- 通过 `DB_PATH` 指定数据库，不默认覆盖生产库。
- 使用 `INSERT OR IGNORE` 或查询后更新实现幂等。
- 输出插入、更新和跳过数量，不输出密码或 JWT。
- 仅在明确设置 `SEED_WORKFORCE_DEMO=true` 时允许连接 Render 数据库。

## 7. 错误处理

- 模板时间无效：提示“请输入有效的上下班时间”。
- 模板被引用删除：提示“该模板正在被排班使用，不能删除”。
- 上班排班未选模板：提示“上班排班请选择班次模板”。
- 普通人员请求他人日程：返回 `403`，前端显示“只能查看自己的日程”。
- 账号无人员档案：显示“人员档案暂未建立”，不误报为登录过期。
- API 401：清除 Token 并要求重新登录；API 404 的档案错误不再触发登录过期提示。

## 8. 验收标准

- 主管可以在设置中新增、编辑、删除未被引用的班次模板。
- 设置后的模板立即出现在排班页下拉框中。
- 主管能够看到当前数据库中的全员排班、考勤和工单时间块。
- 师傅登录后能在“我的”看到自己的班次、考勤和工单安排，不能看到其他人的排班。
- 桌面和窄屏都使用统一的蓝色渐变头和白色圆角卡片。
- 模拟数据脚本运行两次不会产生重复模板、排班、工单或考勤。
- 关键单元/API/静态测试通过；线上部署后可用三个测试账号登录并查看对应日程。
