# 班次与工单派单时间规则设计

## 背景

当前“我的日程”同时展示班次和工单。班次代表员工可以接单的工作时间范围，不是占用该员工时间的业务事项，因此班次覆盖工单属于正常情况，不应形成冲突。

现有页面还存在两个容易混淆的问题：

- 部分页面直接截取 ISO 时间字符串，导致北京时间 `09:00` 被显示为 UTC 时间 `01:00`。
- 冲突提示只说明“日程存在重叠”，没有明确指出是两张工单互相重叠，容易被误解为班次和工单冲突。

## 已确认业务规则

1. 上班班次是可派单时间窗口，例如白班 `08:00–18:00`。
2. 工单处于班次范围内属于正常安排，班次本身不参与冲突计算。
3. 同一人员的两张工单执行时间重叠才属于工单冲突。
4. 员工处于请假、休息或未排班状态时不能派单。
5. 派单时间不在员工班次范围内时不能派单。
6. 不设置紧急工单、主管确认等绕过规则；所有工单统一执行班次校验。
7. 系统业务时区统一为 `Asia/Shanghai`，页面显示北京时间。

## 实现方案

### 1. 服务端派单校验

新增单一职责的派单可用性服务，输入员工档案、派单时刻和预计工时，输出可派状态或稳定错误码。

校验顺序：

1. 找到被派人员在上海日期下的排班记录。
2. 无排班时拒绝，错误码为 `ASSIGNEE_NOT_SCHEDULED`。
3. 排班类型为休息时拒绝，错误码为 `ASSIGNEE_RESTING`。
4. 排班类型为请假时拒绝，错误码为 `ASSIGNEE_ON_LEAVE`。
5. 派单时刻早于班次开始或不早于班次结束时拒绝，错误码为 `ASSIGNMENT_OUTSIDE_SHIFT`。
6. 预计完成时刻超出班次结束时拒绝，错误码同为 `ASSIGNMENT_OUTSIDE_SHIFT`。
7. 与该员工未完成工单预计执行区间重叠时拒绝，错误码为 `ASSIGNMENT_TIME_CONFLICT`，并返回冲突工单编号。

创建处理中工单以及修改工单处理人时，都调用同一个服务端校验，避免不同入口口径不一致。未派单的待处理工单不执行人员班次校验。

当前系统没有独立的“预约上门时间”字段，因此本次以实际派单时刻作为工单开始时刻；预计结束时刻为派单时刻加预计工时。后续若增加预约派单，只需把预约时刻传入相同校验服务。

### 2. 冲突计算

日历冲突计算只比较同一员工的工单执行区间：

- 班次不作为事件加入冲突算法。
- 工单 A 的开始早于工单 B 的结束，且工单 B 的开始早于工单 A 的结束时，判定为重叠。
- 冲突结果返回冲突类型 `ticket_overlap` 和对应工单编号。
- 请假日、休息日或班次外的既有历史工单可以显示异常标识，但不把班次本身称为冲突工单。

### 3. 前端展示

员工首页、“我的”页面和主管日历统一使用上海时区格式化函数，不再通过 `slice(11, 16)` 截取 UTC 字符串。

展示文案调整：

- 班次卡增加“该时段内可派单”的解释。
- 普通状态显示“班次内可派单”。
- 工单重叠显示“工单 A 与工单 B 时间重叠，请联系主管调整”。
- 请假、休息、未排班和班次外分别显示具体不可派原因。

### 4. 模拟数据修正

保留一组真正的工单重叠样本用于验证冲突流程，但所有时间均按北京时间生成和显示。普通当前工单样本调整为班次范围内且互不重叠。

生产环境只修正 `MOCK-E2E-*` 模拟记录，不修改真实历史工单。修正脚本必须幂等，并在执行前创建数据库备份。

## 数据与接口影响

本次不新增数据库表。现有字段继续使用：

- `shift_assignments.start_at`、`shift_assignments.end_at`：员工可派单窗口。
- `tickets.assigned_at`：当前实现中的工单开始时刻。
- `tickets.estimated_hours`：预计占用时长。

派单失败统一返回 HTTP 409，并返回 `error`、`code`，冲突时附带 `conflicting_ticket_ids`，供前端展示明确原因。

## 验收标准

1. 白班 `08:00–18:00` 内派单成功，不出现班次与工单冲突提示。
2. `08:00` 前、`18:00` 后或预计结束超出 `18:00` 的派单被服务端拒绝。
3. 请假、休息、未排班人员无法被派单。
4. 同一员工两张工单时间重叠时拒绝后一次派单，并返回冲突工单编号。
5. 不同员工同一时段的工单不冲突。
6. 员工首页、“我的”和主管日历均显示北京时间，例如 `09:00` 不再显示为 `01:00`。
7. 模拟白班与班次内工单正常并列展示；真正的两工单重叠样本明确标注工单编号。
8. 维修师傅、物业管家和主管的既有工单权限不受影响。

## 测试范围

- 派单可用性服务单元测试：班次内、班次外、跨夜班、休息、请假、未排班、工单重叠。
- 工单创建与修改处理人接口测试：成功和各稳定错误码。
- 日历服务测试：班次不参与冲突、同员工工单重叠、不同员工不冲突。
- 前端模型与时间格式测试：三个入口统一显示上海时间并展示明确冲突原因。
- 模拟数据迁移测试：幂等、仅修改模拟记录、真实记录不变。
